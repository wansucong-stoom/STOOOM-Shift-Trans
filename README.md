# STOOM Shift Translator

## v0.6.5 클립보드 충돌 수정 · 직접 시험용

한글과 Chrome 번역 중 v0.6.4가 `ole32.dll / 0xc000041d`로 종료되는 Windows 기록을 확인했고, 편집기 입력 없이 기존 OLE 백업·복원 시험에서도 같은 예외 코드와 모듈 오프셋을 재현했습니다. 내부 OLE 호출 스택은 확보하지 못했습니다.

기본 경로의 클립보드 백업은 이제 실제 데이터를 메모리에 복사합니다. `OleGetClipboard`로 받은 객체를 다시 `OleSetClipboard`/`OleFlushClipboard`에 전달하는 경로를 사용하지 않습니다. 클립보드 작업은 숨겨진 보조 프로세스 한 개에서 처리하며, 보조 작업이 종료되어도 번역기 전체를 종료시키지 않습니다. 실패한 쓰기나 붙여넣기를 자동으로 반복하지 않습니다.

`OpenClipboard` 점유 오류는 최대 300ms 동안 재시도합니다. 닫은 뒤 갱신되는 Windows 클립보드 변경 번호도 반영해 기존 복원을 누락하지 않도록 했습니다. 기본 입력 경로에서 UIA COM 객체를 매번 만드는 작업도 제거했습니다. 실제 Win32 키보드 포커스와 원문 재확인은 유지합니다.

최종 windowed EXE에서 Unicode·사용자 서식·RTF·HTML·DIB 이미지 보관·교체·복원 20회가 통과했습니다. 이 중 10회는 실제 클립보드 표식→복사 확인→교체→복원 경로를 검증했고, 시작 전 이미지를 다시 복원했습니다. 보조 프로세스 종료·정지·복구와 중복 쓰기 방지 시험 및 자동 시험 38개도 통과했습니다. **한글·Chrome 등 실제 입력창의 단축키부터 교체까지와 문단 서식 보존은 별도 사용자 확인이 필요합니다.**

`STOOM-Translator-v065-TSF-setup.exe`로 기존 설치 위에 업데이트합니다. Python 별도 설치가 필요 없고, 저장된 언어팩과 설정을 삭제하지 않습니다. TSF 구성요소는 변경하지 않아 v0.6.3 구성요소를 포함합니다. 문단 끝을 제외하는 v0.6.4의 처리도 포함합니다.

지원 범위: 일반 텍스트·RTF/HTML·DIB/PNG·파일 목록과 읽을 수 있는 등록 메모리 형식을 보관합니다. 전용 소유자 콜백 형식, 읽을 수 없는 데이터, 가상 파일의 스트림/스토리지 형식은 완전 보존을 보장하지 않습니다. 지원하지 않는 형식이나 64MiB를 넘는 기존 클립보드는 비우기 전에 중단합니다. 문단 안에 섞인 글꼴·색 등 글자별 서식 보존도 미검증입니다. 자세한 검증은 [시험 기록](KEYBOARD_TEST_RESULTS.md)을 참고하세요.

## v0.6.4 직접 시험용

Windows 클립보드 OLE 작업 스레드가 대기 중에도 메시지를 처리하도록 수정하고, OLE 초기화 해제를 올바른 Windows API로 수행합니다. v0.6.3의 ole32.dll 종료 오류와의 직접적인 인과관계는 아직 확인되지 않았습니다.

선택에 문단 끝이 포함된 경우 그 끝을 제외한 결과를 실제 복사로 재확인하고 교체합니다. 문단 구분을 유지하기 위한 조치이며, 한글 등 실제 편집기에서 문단 서식이 유지되는지 아직 검증되지 않았습니다. 여러 글꼴이나 색이 섞인 글자 서식까지 보존한다고 보장하지 않습니다.

`STOOM-Translator-v064-TSF-setup.exe`는 기존 설치 위에 설치하며 저장된 언어팩과 설정을 삭제하지 않습니다. 한글·Word·PowerPoint·Threads의 실제 편집, 서식 보존, 종료 오류 재발 여부는 사용자 시험이 필요합니다.

## v0.6.3 직접 시험용

v0.6.2에서 한글 편집창이 잘못 읽기 전용으로 판단될 수 있는 조건과 Windows에서 클립보드 소유자가 없는 경우 예외가 발생하는 조건을 수정했습니다. 사용자 요청에 따라 공통 키보드 경로에서는 읽기 전용·비밀번호 속성에 따른 차단을 적용하지 않습니다. 클립보드 소유자가 없는 경우 소유자를 통한 출처 검증이 불가능하므로, 새 복사 여부·포커스·입력 변경 및 붙여넣기 전 원문 재확인에 의존합니다. 일부 편집기와 클립보드 관리자 조합에서는 실제 확인이 필요합니다.

설치 파일은 `STOOM-Translator-v063-TSF-setup.exe`입니다. v0.6.2에 이어 **직접 시험용**이며 한글·Word·PowerPoint·Threads에서 실제 교체 성공은 아직 검증되지 않았습니다. 아래 v0.6.2 설명은 공통 키보드 경로의 기본 동작을 설명합니다.

## v0.6.2 공통 키보드 경로 · 사용자 직접 시험용

`STOOM-Translator-v062-TSF-setup.exe`로 기존 설치 위에 업데이트합니다. 사용 PC에 Python이 필요하지 않으며 기존 언어팩·모델 선택·단축키 설정을 유지합니다. 한국어↔영어의 기본 모델은 OPUS-MT Big입니다.

이번 빌드는 선택·복사·붙여넣기를 기본 입력 경로로 사용합니다. 한글·Word·PowerPoint 등 앱 이름에 따른 단축키 분기 없이 같은 절차를 사용하며, TSF의 문맥·편집 세션이나 UIA의 텍스트 범위가 없어도 시도합니다.

- 선택한 글이 있으면 실제 Ctrl+C 결과를 확인하고 번역합니다. 원문은 번역이 끝날 때까지 남겨 둡니다.
- 선택한 글이 없으면 조합 확정을 위한 공백 한 칸을 넣고, 그 한 칸이 실제 복사되는지 확인한 뒤 제거합니다. 캐럿 위치의 세 번 클릭으로 자동 선택하며, 좌표가 없으면 공통 문단 이동·선택 키를 시도합니다.
- 붙여넣기 직전 같은 원문이 선택되어 있는지 다시 복사해 확인합니다. 키·클릭·스크롤 또는 입력 위치가 바뀌면 교체를 취소하고, 번역문은 한 번만 붙여넣습니다.
- 이 경로는 기존의 1.2초 TSF 조합 재시도를 거치지 않습니다. 실제 전체 응답 시간은 아직 측정하지 않았습니다.

**실제 한글·Word·PowerPoint·Threads·Codex에서 이 빌드의 최종 교체 성공은 미검증입니다.** 사용자가 직접 테스트 문서에서 시험하는 빌드입니다. 자동 선택의 범위는 앱에 따라 줄·문단 등으로 다를 수 있으므로, 범위가 맞지 않으면 필요한 글을 직접 선택하고 단축키를 사용하세요. 선택 없이 Ctrl+C가 줄 전체를 복사하는 일부 코드 편집기에서는 반드시 글을 먼저 선택해 시험하세요. 임시 공백은 되돌리기 기록이나 자동 고침에 영향을 줄 수 있습니다.

시험 순서는 새 빈 문서에서 짧은 글 선택 후 단축키, 선택 없이 단축키, 앞뒤 문단 보존 확인, 연속 번역, Ctrl+Z 확인입니다. 상세 변경과 시험 범위는 [공통 키보드 시험 기록](KEYBOARD_TEST_RESULTS.md)에 있습니다. 설정 화면과 Windows 파일 속성에서 **0.6.2 / 20261029.3**을 확인할 수 있습니다.

아래 TSF 설명은 v0.6.1의 구현 기록입니다. v0.6.2 기본 단축키는 위 공통 키보드 경로를 사용합니다.

## 이전 v0.6.1 · TSF 활성화 수정과 업데이트 확인

`STOOM-Translator-v061-TSF-setup.exe`를 실행하면 v0.5/v0.6 설치와 같은 AppId·위치를 사용해 업데이트합니다. **기존 프로그램을 삭제할 필요가 없습니다.** 이전 설치 위치와 바로가기 선택을 재사용하며 `%LOCALAPPDATA%\STOOMShiftTranslator05\models`의 언어팩과 같은 폴더의 `settings.json`을 유지합니다. 설치·제거 스크립트는 이 데이터 폴더를 지우지 않습니다. 구버전이 자동 종료 요청을 지원하지 않으면 트레이에서 **종료**한 후 설치 화면의 다시 시도를 누르세요.

v0.6의 활성화 도구가 정상 등록된 보조 TSF 프로필을 잘못 거부하던 오류를 수정했습니다. 실제 Windows에서 `GetProfile`의 범주가 `GUID_NULL`로 반환되어도 별도 범주 등록은 유효한 경우가 있었습니다. v0.6.1은 명시적인 범주 관계를 확인하고 프로필 활성화 후 자신의 스레드 관리자를 초기화하며, 실제 DLL 서비스 창이 로드되는지 검사합니다. 설치된 서비스에서 활성화 성공과 Microsoft 한글 입력기 유지까지 확인했습니다. 이 검사는 한컴 한글 등 각 편집기에서 실제 텍스트 교체가 성공했다는 뜻은 아닙니다.

설치 파일에는 선택 가능한 **Windows TSF 입력 지원**이 포함됩니다. 이 구성요소만 관리자 승인을 받아 보호된 Program Files 폴더에 등록하며, 번역 앱은 원래 사용자 권한으로 실행합니다. TSF는 32비트와 64비트 모듈을 모두 설치합니다. 설치 후 실행 중이던 편집기는 다시 열어야 새 모듈이 적용될 수 있습니다. 언어팩 다운로드는 다시 할 필요가 없습니다.

TSF 경로는 Windows가 제공하는 `ITfContext`와 `ITfRange`를 이용해 선택한 글 또는 현재 문단을 읽고 `SetText`로 직접 교체합니다. 클립보드와 Ctrl+A/C/V를 사용하지 않습니다. 기존 Microsoft 한글/일본어 입력기를 대체하는 키보드 서비스로 등록하지 않고 별도의 보조 범주로 등록합니다. 기존 Shift/Ctrl 더블탭 감지와 오프라인 모델은 그대로 사용합니다.

TSF 연결이 없는 입력창은 기존 UI Automation 경로를 사용합니다. **TSF에서 보안·원문 변경·적용 실패가 확인된 경우에는 더 느슨한 경로로 우회하지 않습니다.** 적용 응답이 불확실할 때 중복 삽입을 막기 위해 다시 붙여넣지 않습니다. 설정 화면의 입력 지원 상태로 실제 사용한 경로를 볼 수 있습니다.

한글 조합 중에는 최대 약 1.2초 범위에서 짧게 다시 확인하고, 정상 문맥에서는 고정 1~2초 대기를 추가하지 않습니다. 번역 중 원문·선택·포커스가 바뀌면 교체를 중단하며, 비밀번호·비공개·PIN·읽기 전용 문맥을 거부합니다. 문단은 최대 8,000 UTF-16 단위, 번역문은 최대 16,000 단위입니다. 구조화된 객체가 섞였거나 완전한 문단 경계를 읽을 수 없으면 일부만 바꾸지 않습니다.

**검증 구분:** 실제 Windows `msctf.dll`을 사용하는 테스트 소유 문서에서 32·64비트 범위 교체와 보호 조건, 서비스의 반복 활성화/해제, Python 통신, 설치된 서비스의 활성화를 확인했습니다. Threads·ChatGPT·한컴 한글·Store 앱에서 실제 동작하는지는 아직 검증되지 않았습니다. TSF를 제공하지 않는 사용자 정의 입력창, 다른 권한 수준 및 AppContainer까지 지원한다고 보장하지 않습니다. 상세 결과와 재현 명령은 [TSF 검증 기록](native_tsf/TEST_RESULTS.md)에 있습니다.

Windows에서 입력 중인 텍스트를 오프라인으로 번역하는 **실험용** 프로그램입니다. Shift 두 번과 Ctrl 두 번에 각각 다른 목표 언어를 설정할 수 있습니다.

> 완성된 범용 입력기가 아닙니다. Threads, Codex 한글 편집기, 한컴 한글에서의 텍스트 읽기·교체와 보안 입력창 차단은 실제 환경에서 검증되지 않았습니다. 중요한 문서나 비밀번호에서는 사용하지 말고 임시 텍스트로 먼저 시험하세요.

## 사용

1. Windows 64비트에서 빌드된 EXE를 실행합니다. 사용 PC에 Python을 별도로 설치할 필요는 없습니다.
2. **언어팩 관리**에서 방향별 목록으로 사용할 모델을 하나 선택하고, 설치가 필요한 방향을 체크해 내려받습니다. 선택은 번역 엔진 설정과 연결됩니다. 첫 다운로드에는 인터넷이 필요하며, 설치된 팩은 이후 버전에서도 재사용합니다.
3. **단축키 설정**에서 Shift 두 번과 Ctrl 두 번에 목표 언어 또는 사용 안 함을 지정합니다. 시작 시 설정된 각 목표 언어마다 사용 가능한 한 방향으로 시험 번역한 뒤 준비 완료 알림을 표시합니다. 다른 방향은 처음 사용할 때 추가 로딩될 수 있습니다. 외부 엔진은 자동 실행하지 않으므로 첫 번역 시 확인합니다.
4. **번역 엔진**에서 한국어→영어와 영어→한국어에 사용할 모델을 각각 선택할 수 있습니다. 두 방향의 기본값은 **OPUS-MT Big**이며, 이전에 직접 선택한 모델은 유지합니다. 기존 Argos와 OPUS-MT Big은 별도로 설치·보관하며, 미설치 모델을 선택하면 다른 모델로 임의 전환하지 않습니다. 영어↔일본어는 Argos입니다.
5. 일반 입력칸에서 텍스트를 입력하고 단축키를 누릅니다. 문서형 편집기는 선택한 글, 선택이 없으면 현재 문단을 대상으로 시도합니다.

기존 Argos 기본 팩은 한국어→영어, 영어→한국어, 영어→일본어, 일본어→영어입니다. 한국어↔일본어는 영어를 거치며 품질이 떨어질 수 있습니다. 언어팩은 사용자 로컬 폴더에 저장되며 저장소에 포함되지 않습니다. 긴 글은 작은 조각으로 나누어 번역하므로 문맥이 달라질 수 있습니다.

| OPUS-MT Big | 한국어→영어, 영어→한국어 | 방향당 약 741 MiB 원본 다운로드 후 로컬 INT8 변환; 설치 약 212 MiB / 8개 파일 | CTranslate2 INT8, 별도 source/target SentencePiece |

OPUS 모델은 University of Helsinki Language Technology Research Group의 [한국어→영어](https://huggingface.co/Helsinki-NLP/opus-mt-tc-big-ko-en), [영어→한국어](https://huggingface.co/Helsinki-NLP/opus-mt-tc-big-en-ko), 2022-07-28 Marian 원본입니다. CC-BY-4.0에 따라 출처·변환 사실을 언어팩에 함께 저장합니다. 변환은 최초 설치 때만 수행하며 PyTorch, Transformers, spaCy, Stanza를 설치하지 않습니다. 원본 다운로드와 변환 중에는 설치 용량보다 많은 임시 디스크·메모리가 필요합니다. 설치는 백그라운드에서 진행하고 진행 상태를 표시합니다.

이름 표기와 주어 등 번역 오류가 발생할 수 있습니다. 모델 크기나 INT8 여부만으로 품질을 보장하지 않습니다. 같은 언어의 모델을 비교·선택할 수 있으며, 자동으로 품질을 판정해 모델을 바꾸지는 않습니다.

## 빠른 입력 직후의 처리

단축키는 두 번째 Shift/Ctrl을 **뗀 시점**에 완성됩니다. 1~2초 고정 대기 없이 최근 일반 키 입력 이후 120ms의 유휴 시간과 두 번의 같은 텍스트/위치 표본을 최소 80ms 간격으로 확인합니다. 대기 중 다시 글을 쓰거나 입력 위치가 바뀌면 그 요청은 취소되며 오래된 타이머가 다시 실행하지 않습니다. 공급자 읽기가 계속 바뀌거나 실패하면 최대 2.2초에서 종료합니다. 이 수치는 실제 편집기에서 IME 조합 완료를 보장하지 않습니다.

프로그램 자체의 선택 변경 이후에는 저장한 live UIA 범위를 원문으로 재사용하지 않고, 새 범위·원문과 실제 Ctrl+C 결과를 확인합니다. Enter나 IME 전환 키로 조합을 강제 확정하지 않습니다.

## 로컬 비교 결과 (2026-10-29)

동일 PC에서 모델별 별도 소스 Python 프로세스, CPU 4스레드, beam 4, 9개 짧은 예문을 각 5회 실행했습니다. 수치는 각 예문의 중앙값 범위입니다.

| 측정 | 기존 Argos INT8 | OPUS-MT Big INT8 |
| --- | --- | --- |
| 한국어→영어 계산 시간 (6문장) | 0.017~0.044초 | 0.032~0.072초 |
| 영어→한국어 계산 시간 (3문장) | 0.017~0.027초 | 0.045~0.066초 |
| 한국어→영어 최초 로딩+첫 번역 | 0.282초 | 0.489초 |
| 두 방향 로딩 후 프로세스 작업 집합 | 350.6 MiB | 528.0 MiB |
| “저는 누구일까요?” | Who are you? (오역) | Who am I? |

일부 한국어 이름은 OPUS에서도 직업명으로 오역했습니다. 작은 자체 예문 집합이며 전체 품질 점수나 모든 이름의 개선을 뜻하지 않습니다. 기존 모델의 세 오역은 FP32로 실행해도 같았습니다. INT8만의 문제라고 볼 근거는 없습니다.

**이 시간은 모델 계산만 측정한 값입니다.** 단축키부터 실제 입력창 교체까지의 시간, 최종 EXE 추출/시작 시간, v0.4 대비 용량·메모리 비교를 뜻하지 않습니다. 입력 안정화의 이미 유휴 상태에서 번역 시작까지는 가상 시계 시험에서 200ms였습니다. 실제 편집기의 응답 시간은 아직 별도 확인이 필요합니다.

## 안전과 제약

- 비밀번호 속성이 확인된 입력창과 읽기 전용 영역을 차단하고, 번역 중 포커스·선택·원문이 변하면 교체를 취소합니다. 프로그램별 접근성 제공 차이 때문에 모든 보안 입력창과 편집기를 식별한다고 보장할 수 없습니다.
- Windows의 키보드 포커스와 UI Automation을 함께 확인합니다. 포커스가 있다고 해서 편집 가능한 것은 아닙니다. 문서 범위는 TextPattern으로 읽고, 실제 선택된 글을 복사해 확인한 후 붙여넣기를 시도합니다. 필요한 기능을 제공하지 않는 프로그램에서는 작동하지 않습니다.
- 범위 붙여넣기는 클립보드를 잠시 사용하고 기존 내용을 복원하려고 합니다. 그 사이 사용자가 클립보드를 바꾸면 새 내용을 덮어쓰지 않습니다. 모든 클립보드 형식과 편집기의 복원·되돌리기는 아직 검증되지 않았습니다.
- 번역 후 커서 위치는 편집기가 제공하는 접근성 기능에 따라 달라질 수 있습니다. 완료 알림은 표시하지 않고 오류는 알립니다.
- 동시에 실행되는 동일 버전은 하나로 제한합니다. 중복 실행 방지 기능이 없는 이전 시험판은 새 버전 실행 전에 트레이에서 모두 종료해야 합니다.
- 기본 번역은 로컬 CTranslate2 INT8 엔진을 사용하며 최근 언어팩 두 개를 메모리에 보관합니다. 결과의 품질과 속도는 언어팩·PC에 따라 다릅니다. 제공 모델과 데이터의 라이선스는 사용자가 해당 배포처에서 확인해야 합니다.

## 사용자 엔진

설정에서 호환되는 사용자 엔진 EXE를 선택할 수 있습니다. 엔진의 표준 입력에는 UTF-8 JSON `{"text":"안녕하세요","source":"ko","target":"en"}`이 전달되고, 표준 출력에는 `{"translation":"Hello"}`가 필요합니다. 지정 형식을 지원하지 않는 일반 EXE는 그대로 사용할 수 없습니다. 원문은 사용자가 선택한 프로그램에 전달되며 인터넷 사용 여부는 해당 엔진에 달려 있습니다. 이 기능도 실제 외부 엔진과의 통합은 미검증입니다.

## 업데이트 확인과 자동 설치

**업데이트** 화면에서 현재 버전, 새 버전 확인 결과와 다운로드 진행 상태를 볼 수 있습니다. 기본값은 새 버전 자동 확인 켜짐, 자동 설치 꺼짐입니다. 시작 직후의 엔진 준비와 겹치지 않도록 잠시 뒤 확인하고, 앱이 실행 중인 동안 6시간마다 다시 확인합니다. 트레이 메뉴에서도 직접 확인할 수 있습니다.

새 정식 GitHub Release가 있으면 버전별로 한 번 알립니다. **다운로드 후 업데이트**를 누르거나 **새 버전 자동 설치**를 켜면 설치 파일을 내려받아 검증한 뒤 설치를 시작합니다. 자동 설치는 번역·언어팩 설치·입력 교체가 끝날 때까지 기다립니다. 설치 후 앱을 다시 실행하며 기존 언어팩, 단축키와 모델 선택을 보존합니다. TSF 구성요소 업데이트에는 Windows 관리자 승인이 필요할 수 있습니다.

확인 대상은 이 프로젝트의 [GitHub Releases](https://github.com/wansucong-stoom/STOOOM-Shift-Trans/releases)입니다. `v0.6.2` 같은 정식 버전과 해당 버전의 Windows 설치 EXE가 필요합니다. 초안·시험 릴리스, 현재보다 낮은 버전, GitHub의 SHA-256·크기 검증을 통과하지 못한 파일은 자동 설치하지 않습니다. 단순 소스 커밋이나 Actions 빌드 파일은 새 릴리스 알림 대상이 아닙니다. 번역 원문은 업데이트 확인에 포함하지 않습니다.

배포자는 **Windows build**의 `publish_release` 옵션을 켜거나 앱 버전과 같은 `vX.Y.Z` 태그를 푸시하면 시험·빌드 성공 후 설치 파일과 SHA-256 목록이 포함된 릴리스를 게시할 수 있습니다. 이미 게시된 같은 버전은 덮어쓰지 않습니다. 앱 버전, Windows 리소스, 설치 파일명과 네이티브 구성요소 버전을 함께 올려야 합니다. GitHub API 형식은 공식 [Releases](https://docs.github.com/en/rest/releases/releases) 및 [Release assets](https://docs.github.com/en/rest/releases/assets) 문서를 따릅니다.

## 설치형 빌드

설치형은 프로그램 구성 파일을 사용자 폴더에 설치하므로 매번 단일 EXE를 풀지 않습니다. 설정 창은 트레이 아이콘 클릭 또는 실행 파일 재실행으로 다시 열 수 있습니다. `build_windows.bat`은 Python 3.11, Visual Studio C++ Build Tools/Windows SDK, Inno Setup 6이 설치된 개발 PC에서 시험과 설치 파일 생성을 수행합니다. 사용 PC에는 Python과 빌드 도구가 필요 없습니다. TSF DLL은 앱에 로드되므로 매번 새 버전 디렉터리에 설치하며 편집기를 강제로 종료하지 않습니다. 모델 다운로드나 번역이 진행 중이면 업데이트 종료 요청도 작업이 끝날 때까지 기다립니다.

## 빌드

`build_windows.bat`을 실행하면 `dist/STOOM-Translator-v061-TSF-setup.exe`가 생성됩니다. 네이티브 코드를 변경해 배포할 때는 `STOOM_NATIVE_VERSION`을 새 값으로 지정해야 합니다. GitHub Actions의 **Windows build**도 설치형 파일을 빌드하도록 구성되어 있습니다. 실행 파일과 네이티브 서비스는 현재 별도로 서명되어 있지 않습니다.

TSF 설치 구성요소 없이 기존 호환 경로만 포함한 단일 파일을 직접 빌드하려면 다음 명령을 사용합니다.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m PyInstaller --noconfirm --onefile --windowed --icon stoom.ico --add-data "stoom.ico;." --name STOOMShiftTranslator-v05 main.py
```

## 확인 상태

입력 직후 안정화·지연된 호출·취소/재시도, 모델 선택 저장·방향별 라우팅·원본 검증과 설치 롤백, 반복 키 감지, Windows 키보드 포커스 확인, 범위 선택과 원문 변경, 엔진 준비 알림, 중복 실행 차단, 클립보드 복원 분기, 긴 텍스트 분할은 모의 시험을 거쳤습니다. 한영 모델은 긴 한국어 예문을 로컬에서 처리했습니다. Windows 최종 EXE의 별도 진단 모드에서 실제 OPUS 한국어→영어 원본 설치/INT8 변환과 “Who am I?” 번역, 영어→한국어 로딩/번역을 확인했습니다. Python 실행 경로를 제외한 환경에서 종료 코드 0으로 완료했습니다. **최종 EXE의 전체 GUI/입력 기능, 실제 대상 앱별 입력과 클립보드 보존, v0.4와의 메모리·지연 비교는 미검증입니다.**


진단이 필요한 개발자는 `EXE --check-pack ID MODELS_DIRECTORY REPORT_JSON [VERIFIED_ARCHIVE]`로 키보드 후크와 편집기 조작 없이 해당 팩의 로딩/번역을 확인할 수 있습니다. 마지막 인수를 주면 카탈로그의 크기/SHA-256이 일치하는 원본 아카이브만 먼저 설치합니다. 보고서에는 준비 확인용 예문의 결과만 기록하며 열린 문서의 내용을 읽지 않습니다.
